# LeetCode 27 - Remove Element / 移除元素

## 题意
给定一个数组 `nums` 和一个值 `val`，要求移除数组中所有等于 `val` 的元素，并返回剩余有效元素的个数。

---

## 核心思路
这题的关键不是“直接删除元素”，而是：

**把不等于 `val` 的有效元素往前覆盖。**

用两个下标：

- `i`：当前正在检查哪个元素
- `k`：下一个有效元素应该放到哪个位置

遍历数组时：

- 如果 `nums[i] == val`，跳过
- 如果 `nums[i] != val`，就把 `nums[i]` 放到 `nums[k]`
- 然后让 `k += 1`

最后返回 `k`，因为 `k` 就是有效元素个数。

---

## 关键理解
### 1. 这题不是“真的删除”
我一开始总在想怎么把元素删掉，但这题更好的做法不是删除，而是覆盖。

### 2. `i` 和 `k` 分工不同
- `i` 负责看
- `k` 负责放

### 3. `k` 有双重意义
- 表示当前已经找到多少个有效元素
- 也表示下一个有效元素该放到哪里

---

## 代码
```python
class Solution:
    def removeElement(self, nums, val):
        k = 0

        for i in range(len(nums)):
            if nums[i] != val:
                nums[k] = nums[i]
                k += 1

        return k
```

## 我今天的卡点
- 一开始总想直接删除元素
- 不理解为什么要“往前放”

## 我最后真正理解的点
- 这题不是删除，而是覆盖有效元素
- i 负责看，k 负责放

## 补充

学了双指针后的思路：
\- 同向双指针
\- i 负责扫描整个数组
\- k 负责指向下一个该放保留元素的位置
\- 当 `nums[i] != val` 时：
  \- 把 `nums[i]` 放到 `nums[k]`
  \- 然后 `k += 1`

关键点：
\- `nums[k] = nums[i]` 是覆盖，不是交换
\- 因为这里只是把有效元素写到前面
\- 最后前面 `[0 ... k-1]` 就是有效部分
\- 返回 `k`，因为 `k` 表示有效元素数量

时间复杂度：
\- O(n)

空间复杂度：
\- O(1)

# 一、283. Move Zeroes

## 题意

把数组中的所有 `0` 移动到末尾，同时保持非零元素原本的相对顺序。

例如：

```python
nums = [0, 1, 0, 3, 12]
```

处理后应变成：

```python
[1, 3, 12, 0, 0]
```

---

## 我的当前理解

这题使用**同向双指针**。

- 指针 `i` 用来从左到右遍历整个数组，寻找非零元素
- 指针 `k` 用来表示**下一个应该存放非零元素的位置**

当 `nums[i] != 0` 时，就把这个非零元素放到 `nums[k]`，然后 `k += 1`。

---

### 关键理解 1：`i` 和 `k` 的分工

- `i` 负责找，所以每轮都会移动
- `k` 负责放，所以只有遇到非零元素时才会移动

一句话记忆：

> `i` 负责找，`k` 负责放。

---

### 关键理解 2：第一轮结束后发生了什么

第一轮遍历结束后：

- 前面 `[0, k-1]` 的位置已经按原顺序放好了所有非零元素
- 从 `k` 开始到数组末尾，是后续需要补 `0` 的区域

注意：

这里 `k` 后面的位置**可能还残留旧值**，不代表 `i` 没有遍历到它们。  
这些旧值只是原地覆盖后暂时没被清掉，第二轮会统一改成 `0`。

所以第一轮结束后，我们只相信：

```text
[0, k-1]
```

这一段有效区。

---

### 关键理解 3：为什么后面还可能看见非零旧值

因为第一轮做的事情是：

> 把非零元素按顺序复制到前面

而不是：

> 一边复制，一边立刻把后面清空

所以会出现：

- `i` 已经把所有元素都遍历完了
- 所有非零元素也都已经处理过了
- 但 `k` 后面某些位置还残留旧的非零值

这些值只是**待清理区中的旧数据**，不代表有新元素没处理到。

---

### 关键理解 4：为什么顺序不会乱

因为 `i` 是从左到右扫描的。  
我们也是按扫描到的顺序，把非零元素依次放到前面。

所以非零元素的相对顺序自然不会改变。

---

### 完整思路

第一轮：

- 遍历整个数组
- 如果当前元素不是 `0`
  - 就把它放到 `nums[k]`
  - 然后 `k += 1`

第二轮：

- 从 `k` 开始到数组末尾
- 把所有位置都补成 `0`

---

### 最小代码

```python
class Solution:
    def moveZeroes(self, nums):
        k = 0

        for i in range(len(nums)):
            if nums[i] != 0:
                nums[k] = nums[i]
                k += 1

        while k < len(nums):
            nums[k] = 0
            k += 1
```

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

### 我当前最需要记住的话

1. 这题是**同向双指针**

2. `i` 负责找，`k` 负责放

3. 第一轮结束后，`k` 也等于非零元素的数量

4. 第一轮是覆盖，不是交换

5. 第二轮统一补 `0`

# 二、242. Valid Anagram

### 题意

判断两个字符串是否为**字母异位词**。

字母异位词要求：

- 两个字符串长度必须相同
- 必须由相同种类的字符组成
- 每种字符出现的次数也必须相同
- 只是字符顺序可以不同

例如：

```python
s = "anagram"
t = "nagaram"
```

返回 `True`。

---

### 我的当前理解

先明确字母异位词的定义，再去写代码。

#### 第一步：先判断长度

如果：

```python
len(s) != len(t)
```

那么直接返回 `False`。

因为字母异位词本质上只是字符顺序不同，但字符总数不能变。  
长度都不同，就已经不可能是字母异位词。

---

### 第二步：建立字典 `count = {}`

创建一个字典：

```python
count = {}
```

用来记录第一个字符串 `s` 中各个字符出现的次数。

例如：

```python
s = "aab"
```

统计完后可以理解成：

```python
count = {
    "a": 2,
    "b": 1
}
```

---

### 第三步：遍历第二个字符串 `t`

再去遍历 `t`：

- 如果 `t` 中出现了一个根本不在 `count` 里的字符，直接返回 `False`
- 如果字符在 `count` 中，就把次数减 `1`
- 如果减完后出现：

```python
count[ch] < 0
```

也要返回 `False`

---

### 为什么 `count[ch] < 0` 很重要

这是我自己复现代码时容易忽略的点。

它表示：

> 某个字符在 `t` 中出现次数比在 `s` 中更多

也就是说：

- 字符种类看起来可能一样
- 总长度也一样
- 但某个字符的具体数量不匹配

这时一定不是字母异位词。

这个条件必须重点记住。

---

### 这题的本质理解

可以把它想成“记账”：

- `s` 负责加账
- `t` 负责减账

如果最后能全部刚好抵消，说明两个字符串匹配。  
如果中途出现：

- 字符不存在
- 或者次数减成负数

就说明不匹配。

---

### 最小代码

```python
class Solution:
    def isAnagram(self, s, t):
        if len(s) != len(t):
            return False

        count = {}

        for ch in s:
            if ch not in count:
                count[ch] = 0
            count[ch] += 1

        for ch in t:
            if ch not in count:
                return False
            count[ch] -= 1
            if count[ch] < 0:
                return False

        return True
```

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

这里的 `n` 可以理解为字符串长度。

---

### 我当前最需要记住的话

1. 先判断长度，不同直接 `False`
2. 用字典记录 `s` 中字符出现次数
3. `t` 中如果出现了 `count` 里没有的字符，直接 `False`
4. `count[ch] < 0` 说明某个字符数量不匹配，也直接 `False`
5. 这题本质是：`s` 加账，`t` 减账

---

# 一、283 Move Zeroes

## 题目本质

把数组中的所有 `0` 移动到末尾，同时保持所有非零元素的相对顺序不变。

---

## 思路

这题的核心是**同向双指针**。

- `i`：负责从左到右扫描整个数组，寻找非零元素
- `k`：负责指向“下一个应该放非零元素的位置”

做法分两步：

### 第一步：把所有非零元素按顺序覆盖到前面

当 `nums[i] != 0` 时：

- 把 `nums[i]` 放到 `nums[k]`
- 然后 `k += 1`

这样第一轮结束后：

- `[0, k-1]` 都是已经整理好的非零元素
- `k` 也等于非零元素的个数

### 第二步：把后面的部分全部补成 0

从 `k` 开始，到数组末尾，全部赋值为 `0`

---

## 关键变量

- `i`：扫描指针，负责找非零元素
- `k`：写入指针，负责把非零元素放到正确位置

---

## 关键理解

### 1. 这是“覆盖”，不是“交换”

这里不是把两个数互换位置，而是：

- 找到一个非零元素
- 直接覆盖到前面的正确位置

### 2. `k` 指向的不是“0 的位置”

更准确地说：

**`k` 指向的是“下一个该放非零元素的位置”。**

---

## 最小代码

```python
class Solution:
    def moveZeroes(self, nums):
        k = 0

        for i in range(len(nums)):
            if nums[i] != 0:
                nums[k] = nums[i]
                k += 1

        for i in range(k, len(nums)):
            nums[i] = 0
```

---

## 时间复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

## 易错点

1. 容易误以为这是交换，其实本质是覆盖
2. 容易把 `k` 理解成“指向 0 的位置”，其实更准确是“下一个非零元素该放的位置”
3. 第一轮结束后，后半段可能还是旧值残留，所以必须第二轮统一补 0

# 二、125 Valid Palindrome

## 题目本质

在**忽略大小写**、**跳过非字母数字字符**的前提下，判断字符串是不是回文串。

回文串的本质是：

**首尾对称。**

所以这题适合使用**左右双指针**。

---

## 思路

使用两个指针：

- `left` 从左边开始
- `right` 从右边开始

外层循环条件是：

- 只要 `left < right`，就继续检查

每一轮都按下面顺序执行：

### 第一步：左指针跳过所有非字母数字字符

如果 `s[left]` 不是字母或数字，就一直右移。

### 第二步：右指针跳过所有非字母数字字符

如果 `s[right]` 不是字母或数字，就一直左移。

### 第三步：比较当前左右两个有效字符

比较时要先转成小写：

- 如果不相等，直接返回 `False`
- 如果相等，说明当前这一对字符通过检查

### 第四步：左右指针继续向中间移动

- `left += 1`
- `right -= 1`

### 第五步：回到外层循环

继续判断下一对字符。

如果整个循环都顺利执行完，没有发现不相等的情况，最后返回 `True`。

---

## 关键变量

- `left`：左指针，从左往右寻找下一个有效字符
- `right`：右指针，从右往左寻找下一个有效字符

此外还会用到两个字符串方法：

- `isalnum()`：判断字符是否是字母或数字
- `lower()`：把字符转成小写，用于忽略大小写影响

---

## 最小代码

```python
class Solution:
    def isPalindrome(self, s):
        left = 0
        right = len(s) - 1

        while left < right:
            while left < right and not s[left].isalnum():
                left += 1

            while left < right and not s[right].isalnum():
                right -= 1

            if s[left].lower() != s[right].lower():
                return False

            left += 1
            right -= 1

        return True
```

---

## 时间复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

## 易错点

### 1. 要先跳过非字母数字字符

这是题目要求。  
不能直接拿所有字符去比较。

---

### 2. 跳过无效字符时要用 `while`，不能只用 `if`

因为字符串里可能连续出现多个非字母数字字符。

- `if` 只能跳过一次
- `while` 才能一直跳过，直到找到有效字符

---

### 3. 外层循环条件是 `left < right`

只要左右指针还没相遇，就继续判断。

---

### 4. 比较字符时要先用 `lower()`

因为题目要求忽略大小写。

---

### 5. `left += 1` 和 `right -= 1` 不属于 `if` 内部

这里是我这题里比较容易混淆的地方。

正确理解是：

- `if` 只处理“不相等”的情况
- 如果不相等，直接 `return False`
- 如果代码能继续往下执行，说明当前这对字符已经比较通过
- 所以此时左右指针应该继续向中间移动

也就是说：

- `return False` 是**中途发现错误，提前退出**
- `return True` 是**整个循环都顺利结束后的最终通过**

---

## 这题里的循环执行顺序

这题真正容易混淆的点，不只是双指针本身，而是循环和判断的执行顺序。

每一轮大循环都可以拆成：

1. 左边跳过无效字符
2. 右边跳过无效字符
3. 比较当前左右字符
4. 如果不相等，返回 `False`
5. 如果相等，左右指针继续向中间移动
6. 回到外层 `while` 继续下一轮判断

可以压缩成一句：

**清左边 -> 清右边 -> 比较 -> 推进 -> 回到大循环**

## 一、704. Binary Search

### 题目目标

给定一个 **升序数组** `nums` 和一个目标值 `target`：

- 如果 `target` 在数组里，返回它的下标
- 如果不在，返回 `-1`

---

### 核心前提

这题能用二分查找的前提是：

**数组必须有序（升序）**

因为只有有序，才可以通过中间值判断：

- 目标在左边
- 还是在右边

---

### 核心思路

二分查找不是一个个找，而是：

**每次看中间，然后排除一半**

如果：

- `nums[mid] == target`：直接找到
- `nums[mid] < target`：说明目标在右边
- `nums[mid] > target`：说明目标在左边

---

### 为什么 `mid` 要写在循环里

因为：

- `left` 和 `right` 每一轮都会更新
- 搜索区间会变化
- `mid` 是当前区间的中点

所以：

```python
mid = (left + right) // 2
```

必须每轮重新计算。

一句话理解：

**范围变了，中点就要重新算。**

---

### 为什么 `right = len(nums) - 1`

因为：

- `len(nums)` 是数组长度
- 最后一个合法下标是 `len(nums) - 1`

例如数组长度是 6：

- 下标是 `0, 1, 2, 3, 4, 5`
- 不是 `6`

---

### 为什么 `nums[mid] < target` 时写 `left = mid + 1`

因为：

- `mid` 这个位置已经检查过了
- 它不等于 `target`
- 并且它比 `target` 小
- 所以 `mid` 和它左边都不可能再是答案

因此必须从右边一格开始继续找：

```python
left = mid + 1
```

而不能写成：

```python
left = mid
```

否则可能卡住，甚至死循环。

---

### 为什么最后返回 `-1`

循环条件是：

```python
while left <= right:
```

循环结束说明：

```python
left > right
```

也就是：

**搜索区间已经空了**

如果这时候还没找到 `target`，就说明数组里没有它，所以返回：

```python
-1
```

---

### 代码

```python
class Solution:
    def search(self, nums, target):
        left = 0
        right = len(nums) - 1

        while left <= right:
            mid = (left + right) // 2

            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                left = mid + 1
            else:
                right = mid - 1

        return -1
```

---

### 时间复杂度

```python
O(log n)
```

因为每次排除一半。

### 空间复杂度

```python
O(1)
```

因为只用了几个变量：

- `left`
- `right`
- `mid`

---

## 二、35. Search Insert Position

### 题目目标

给定一个 **升序数组** `nums` 和目标值 `target`：

- 如果找到了 `target`，返回它的下标
- 如果没找到，返回它**应该插入的位置**

---

### 和 704 的关系

这题本质上是：

**Binary Search 的变形题**

前面的二分过程几乎一样，真正关键的区别只在最后：

- 704：没找到返回 `-1`
- 35：没找到返回 `left`

---

### 最核心的逻辑

一开始：

- `left` 只是搜索区间左边界
- `right` 只是搜索区间右边界

并不是一开始就说 `left` 是插入位置。

在二分过程中：

#### 当 `nums[mid] < target`

说明：

- `mid` 太小了
- `mid` 左边也都太小了

所以：

**`mid` 以及它左边，不可能是目标，也不可能是插入位置**

于是可以整段排除：

```python
left = mid + 1
```

---

#### 当 `nums[mid] > target`

说明：

- `mid` 太大了
- `mid` 右边也都太大了

所以：

**`mid` 右边那些位置，不可能是目标，也不可能是插入位置**

于是可以整段排除：

```python
right = mid - 1
```

---

#### 当 `nums[mid] == target`

直接返回：

```python
return mid
```

---

### 为什么最后返回 `left`

这是这题最重要的点。

在循环过程中，会逐渐形成两个已经确定的区域：

- `left` 左边的区域：都 `< target`
- `right` 右边的区域：都 `> target`
  （如果有 `== target`，前面已经直接返回了）

当循环结束时：

```python
left > right
```

说明：

**中间未判定区间已经空了**

此时：

- `right` 已经退到 `left` 的左边
- `left` 正好落在“小于 target”和“大于 target”这两部分的分界点上

所以：

**`left` 就是插入位置**

---

### 为什么不是 `right`

因为：

- `right` 表示的是最后一个还在左边区域的位置
- 插入点应该在它后面一格

而循环结束时恰好有：

```python
left = right + 1
```

所以真正的插入位置是：

```python
left
```

---

### 代码

```python
class Solution:
    def searchInsert(self, nums, target):
        left = 0
        right = len(nums) - 1

        while left <= right:
            mid = (left + right) // 2

            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                left = mid + 1
            else:
                right = mid - 1

        return left
```

---

### 时间复杂度

```python
O(log n)
```

### 空间复杂度

```python
O(1)
```

---

## 704 和 35 的本质区别

### 704 Binary Search

目标是：

**找这个数在不在数组里**

所以：

- 找到就返回下标
- 找不到就返回 `-1`

---

### 35 Search Insert Position

目标是：

**如果这个数不在数组里，它应该放在哪里**

所以：

- 找到就返回下标
- 找不到就返回分界点 `left`

---

## 今天最该记住的 6 句话

1. 二分查找的前提是：**数组有序**
2. 每一轮都看中间位置 `mid`
3. `nums[mid] < target`，去右边
4. `nums[mid] > target`，去左边
5. 704 没找到返回 `-1`
6. 35 没找到返回 `left`

---

## 我今天真正补到的理解

### 对 704 的理解

- `left` 和 `right` 是搜索区间边界
- `mid` 必须放在循环里重新计算
- 循环结束即 `left > right`
- 如果还没找到，就返回 `-1`

### 对 35 的理解

- `left` 一开始不是插入位置，只是左边界
- 通过不断排除不可能的位置，最后 `left` 会停在分界点
- 循环结束时：
  - `left` 左边都 `< target`
  - `left` 右边都 `> target`
- 所以 `left` 就是插入位置

---

## 最简总结

今天我学到的不是“背下两道题代码”，而是：

### 704

找得到就返回下标，找不到返回 `-1`

### 35

找得到就返回下标，找不到返回分界点 `left`

它们前面的二分过程几乎一样，真正的区别只在最后返回值不同。

# 1. 69. Sqrt(x)

## 题目本质

这题不是要求真正的小数平方根，而是要求：

**返回 `sqrt(x)` 向下取整后的整数部分。**

例如：

- `x = 4`，答案是 `2`
- `x = 8`，答案是 `2`

所以这题本质是在找：

**最大的整数 `k`，满足 `k * k <= x`**

---

## 为什么可以用二分查找

因为随着 `mid` 变大，`mid * mid` 也会变大。

也就是说：

- 如果某个 `mid` 满足 `mid * mid <= x`
- 那么更小的数也一定满足
- 如果某个 `mid` 满足 `mid * mid > x`
- 那么更大的数也一定不满足

这说明这里有**单调性**，所以可以二分。

---

## 这题和普通二分的区别

这题不是在找“精确值”，而是在找一个**边界**：

**最后一个满足 `mid * mid <= x` 的整数。**

所以它比 704 Binary Search 更像“边界题”。

---

## 为什么 `mid * mid < x` 时不能直接返回

因为这只能说明：

**当前 `mid` 合法，但不一定是最大的合法值。**

例如：

- `x = 99`
- `mid = 8` 时，`8 * 8 = 64 < 99`

虽然 8 合法，但真正答案是 9，因为：

- `9 * 9 = 81 <= 99`
- `10 * 10 = 100 > 99`

所以当 `mid * mid < x` 时：

- 不能直接返回
- 应该先把 `mid` 记成候选答案
- 再继续往右边找

---

## 为什么要用 `ans`

因为我们在二分过程中会不断遇到“当前合法，但不确定是不是最大合法值”的情况。

所以要用：

```python
ans = mid
```

来记录“目前找到的最大合法值”。

最后循环结束后，返回 `ans`。

---

## 代码骨架

```python
class Solution(object):
    def mySqrt(self, x):
        if x < 2:
            return x

        left = 0
        right = x
        ans = 0

        while left <= right:
            mid = (left + right) // 2

            if mid * mid == x:
                return mid
            elif mid * mid < x:
                ans = mid
                left = mid + 1
            else:
                right = mid - 1

        return ans
```

---

## 核心逻辑总结

- 这题本质是在找最大的 `k`，满足 `k * k <= x`
- `mid * mid` 随 `mid` 增大而增大，所以可以二分
- `mid * mid < x` 时不能直接返回，因为右边可能还有更大的合法值
- 所以要用 `ans` 记录当前答案候选人

---

# 2. 1. Two Sum

## 题目本质

给定数组 `nums` 和目标值 `target`，找出两个数，使它们相加等于 `target`，并返回它们的下标。

例如：

```python
nums = [2, 7, 11, 15]
target = 9
```

因为：

```python
2 + 7 = 9
```

所以返回：

```python
[0, 1]
```

---

## 暴力解法的问题

最直接的方法是双重循环：

- 先拿一个数
- 再去后面一个个试

这样可以做出来，但时间复杂度是：

```python
O(n^2)
```

效率较低。

---

## 哈希表为什么适合这题

哈希表的核心优势是：

**可以快速查询某个值之前是否出现过。**

这题非常适合这种思路，因为对于当前数字 `num`，我们真正关心的是：

```python
need = target - num
```

也就是：

**还差哪个数，才能和当前数字凑成 `target`。**

---

## 哈希表中存什么

哈希表里存的是：

**数字 -> 下标**

例如：

```python
seen = {
    2: 0,
    7: 1
}
```

表示：

- 数字 2 出现在下标 0
- 数字 7 出现在下标 1

这样当发现 `need in seen` 时，就可以立刻拿到之前那个数的下标。

---

## 为什么要“先查再存”

正确顺序是：

1. 先计算 `need = target - num`
2. 先查 `need` 是否在 `seen` 中
3. 如果不在，再把当前 `num` 和下标存进去

原因：
如果先存再查，当前元素可能会和自己配对。

所以这题必须牢记：

**先查，再存。**

---

## 代码骨架

```python
class Solution(object):
    def twoSum(self, nums, target):
        seen = {}

        for i, num in enumerate(nums):
            need = target - num

            if need in seen:
                return [seen[need], i]

            seen[num] = i
```

---

## 核心逻辑总结

- 哈希表适合做“快速查询之前是否出现过”
- 当前数字已知，`target` 已知，所以可以算出 `need = target - num`
- 如果 `need` 之前出现过，说明答案找到了
- 如果没出现过，就把当前数字和下标存进哈希表
- 整个过程是一边遍历，一边查，一边存

---

# 202. Happy Number

## 题目目标

给定一个正整数 `n`，反复执行如下规则：

- 把这个数的每一位取出来
- 每一位分别平方
- 再把这些平方加起来，得到一个新数

如果最后能变成 `1`，则它是快乐数，返回 `True`；否则返回 `False`。

---

## 我一开始容易卡住的点

1. 为什么不是快乐数时一定会循环，而不是无限变大
2. `set` 在这题里到底是干什么的
3. `get_next` 这种辅助函数是做什么的
4. `% 10` 和 `// 10` 如何帮助拆位
5. LeetCode 模板里的 `self.get_next(n)` 看起来很陌生

---

## 题目本质

这题不是要背哪些数是快乐数，哪些不是。

它的本质是：

- 对任意一个数，反复执行同一个固定规则
- 如果能到 `1`，就是快乐数
- 如果某个旧数字再次出现，说明开始循环了，不是快乐数

---

## 为什么不是快乐数最终会循环

### 第一层原因

快乐数规则不会让数字无限变大。

因为每一位最大只有 `9`，平方后最大只有：

```text
9² = 81
```

所以如果一个数有 `d` 位，那么下一步最大也不过是：

```text
81 × d
```

例如：

- 4 位数下一步最大是 `324`
- 5 位数下一步最大是 `405`

这说明：

> 大数经过几轮变换后，会迅速缩到一个有限的小范围里

---

### 第二层原因

一旦数字被限制在一个有限范围里，如果一直没有变成 `1`，
那在足够多次操作后，必然会重新遇到以前出现过的数。

因为：

- 可取的数字是有限个
- 变化规则又是固定的
- 所以一旦旧数字重复出现，后面路线也会重复

这就形成循环。

---

## 这题判断主逻辑

1. 不断把当前数字变成“各位平方和”
2. 如果变成 `1`，返回 `True`
3. 如果某个数字以前出现过，说明进入循环，返回 `False`
4. 为了快速判断是否出现过，用 `set` 记录旧数字

---

## 为什么这题用 `set`

因为这题只关心：

> 当前这个数以前有没有出现过

并不关心：

- 它第几次出现
- 它对应什么下标
- 它出现了多少次

所以只需用 `set` 做查重即可。

---

## 为什么是先查后存

因为 `set` 记录的是“以前出现过的数字”。

流程应该是：

1. 先检查当前数是否已经在 `set` 中
2. 如果在，说明重复了，直接返回 `False`
3. 如果不在，再把它加入 `set`
4. 然后再计算下一步数字

---

## 如何计算“下一步数字”

辅助函数负责把一个数字变成“各位平方和”。

例如 `82`：

- 取 `2`，平方后加 `4`
- 再取 `8`，平方后加 `64`
- 最终得到 `68`

所以：

```text
82 -> 68
```

---

## 逐位拆数字的逻辑

### 取最后一位

```python
digit = n % 10
```

例如：

```python
82 % 10 = 2
```

---

### 去掉最后一位

```python
n = n // 10
```

例如：

```python
82 // 10 = 8
8 // 10 = 0
```

---

### 为什么不需要知道整数有几位

因为不是先数位数再拆，
而是每次取最后一位，再删掉最后一位，直到 `n == 0` 为止。

所以不管是：

- 1 位数
- 2 位数
- 10 位数

都可以用同样方法处理。

---

## 最小代码

```python
class Solution(object):
    def isHappy(self, n):
        seen = set()

        while n != 1:
            if n in seen:
                return False
            seen.add(n)
            n = self.get_next(n)

        return True

    def get_next(self, n):
        total = 0
        while n > 0:
            digit = n % 10
            total += digit * digit
            n //= 10
        return total
```

---

## 当前最关键的理解

- 主函数 `isHappy` 负责整体流程判断
- 辅助函数 `get_next` 负责算下一步数字
- `set` 负责记录已经出现过的数字
- 一旦旧数字重复出现，就说明进入循环，不是快乐数

---

## 我当前对这题的标准复盘

这题的主逻辑是：快乐数规则不会让数字无限变大，
即使一开始是很大的数，经过几轮变换后也会缩到有限范围内。
如果一直没有变成 `1`，那么在足够多次操作后一定会出现旧数字重复。
由于同一个数在固定规则下，下一步结果也是固定的，
所以只要旧数字重复出现，后面的路径就会重复，这说明进入循环，不是快乐数。
因此这题只需要用 `set` 去记录“某个数字以前有没有出现过”。
如果 `n == 1`，返回 `True`；否则先查后存，再算下一步数字。

---

## 当前易错点

1. 误以为不是快乐数时会无限变大
2. 误把 `set` 当成必须记录次数的容器
3. 忘记是“先查后存”
4. 把 `% 10` 和 `// 10` 的作用混掉
5. 被 `self.get_next(n)` 的类写法干扰主逻辑

# 217. Contains Duplicate

## 题目目标

给定一个整数数组 `nums`，判断数组中是否存在重复元素。

- 有任意一个数出现至少两次，返回 `True`
- 如果所有元素都只出现一次，返回 `False`

---

## 题目本质

这题本质上只是在问：

> 当前这个数字以前有没有出现过？

如果以前出现过，说明数组里有重复，直接返回 `True`。

---

## 为什么这题更适合 `set`

虽然也可以用 `dict` 计数，
但这题并不关心：

- 某个数字出现了几次
- 它对应什么额外信息

它只关心：

> 有没有重复

所以用 `set` 更自然。

---

## 核心思路

1. 准备一个 `set` 记录已经出现过的数字
2. 遍历数组中的每个数字
3. 如果当前数字已经在 `set` 里，直接返回 `True`
4. 如果不在，就加入 `set`
5. 如果整个数组遍历完都没有重复，返回 `False`

---

## 为什么重复时可以立刻返回 `True`

因为题目只问是否存在重复元素。

所以只要当前数字已经在 `set` 中，就能立刻确定：

> 数组中存在重复元素

这时不需要继续检查后面的元素。

注意：

- 关键不是当前元素是不是最后一个
- 关键是它是否已经出现在 `set` 中

---

## `return False` 的条件

`return False` 不属于某个单独元素触发，
而是表示：

> 整个数组都遍历完了，仍然没有发现重复元素

也就是说：

- 循环里一旦重复，提前 `return True`
- 循环结束后还没返回，才执行 `return False`

---

## 最小代码

```python
class Solution(object):
    def containsDuplicate(self, nums):
        seen = set()

        for num in nums:
            if num in seen:
                return True
            seen.add(num)

        return False
```

---

## 代码关键点

### `for num in nums`

表示：

- 依次遍历数组 `nums`
- 每次把当前元素放进变量 `num`

---

### `if num in seen`

表示：

- 当前数字以前已经出现过
- 因此数组里存在重复元素
- 立刻返回 `True`

---

### `seen.add(num)`

表示：

- 如果当前数字以前没出现过
- 就把它加入“已出现过的名单”

---

## 与 Happy Number 的共通点

### 相同点

- 都是在做“查重”
- 都是“先查后存”
- 都适合用 `set`

### 不同点

- `Happy Number`：重复说明进入循环，所以返回 `False`
- `Contains Duplicate`：重复说明数组存在重复元素，所以返回 `True`

当题目只要求判断：

> 某个东西以前有没有出现过

2. 误以为必须用 `dict` 计数
3. 误把 `return False` 理解成某个元素触发

# 169. Majority Element

## 题目本质

这题的目标是：

**找出数组中出现次数超过一半的那个数字。**

所以这题不是单纯判断“有没有重复”，  
而是要判断：

- 每个数字出现了几次
- 谁的次数 **大于** `len(nums) // 2`

因此，这题更适合用：

- `dict` 计数

而不是：

- `set` 查重

---

## 为什么不用 `set`

`set` 只能帮我判断：

- 某个数有没有出现过
- 有没有重复

但这题要的是：

- 某个数出现了几次

例如：

```python
[3, 2, 3]
```

我需要知道：

- `3` 出现了 2 次
- `2` 出现了 1 次

所以这题的核心不是“见过没有”，而是“次数是多少”。

---

## 主逻辑骨架

1. 创建一个空字典 `count`
2. 遍历 `nums`
3. 对当前数字 `num` 进行计数
4. 每次更新后，立刻检查它是否已经超过一半
5. 如果超过，直接返回这个数字

---

## 为什么第一次出现要记成 1

如果当前遍历到了某个数字，说明：

**这一轮已经遇到它一次了。**

所以如果它之前不在字典里，就应该记成：

```python
count[num] = 1
```

而不是 0。

因为这不是“还没出现”，  
而是“现在第一次出现”。

---

## 最小代码

```python
class Solution:
    def majorityElement(self, nums):
        count = {}

        for num in nums:
            if num in count:
                count[num] += 1
            else:
                count[num] = 1

            if count[num] > len(nums) // 2:
                return num
```

---

## 关键代码拆解

### 1. 建立字典

```python
count = {}
```

表示创建一个空字典，用来记录：

- 数字 -> 出现次数

---

### 2. 遍历数组

```python
for num in nums:
```

表示依次遍历 `nums` 中的每一个元素。

注意：

- `num` 只是变量名
- 也可以换成 `x`、`value` 等别的名字

例如：

```python
for x in nums:
```

也是一样的逻辑。

---

### 3. 更新次数

```python
if num in count:
    count[num] += 1
else:
    count[num] = 1
```

意思是：

- 如果这个数以前出现过，就加 1
- 如果以前没出现过，就从 1 开始记

---

### 4. 判断是否超过一半

```python
if count[num] > len(nums) // 2:
    return num
```

题目要求的是：

**超过一半**

所以必须是：

```python
>
```

而不是：

```python
>=
```

---

## 易错点

### 错误 1：把这题当成查重题

这题不是 217 那种“重复就返回”的题。

这题是：

**计数题**

---

### 错误 2：使用 `while`

这题不需要：

```python
while ...
```

因为我们不是盯着同一个数字反复处理，  
而是：

**在 `for` 遍历数组时，每遇到一次它，就更新一次。**

---

### 错误 3：第一次出现记成 0

第一次出现时，说明它已经被遇到了 1 次，  
所以必须记成：

```python
count[num] = 1
```

---

## 我今天在这题里真正补到的理解

1. 这题本质是“频率统计”，不是查重。
2. `set` 更适合“有没有出现过”，`dict` 更适合“出现了几次”。
3. `for num in nums` 会遍历数组中的每一个元素，不会因为某个值重复就自动跳过。
4. 如果程序中途 `return`，那只是函数提前结束，不是 `for` 遍历不到。
5. `count[num] = 1` 的意思是“当前这一次已经遇到了它”。

## 125. Valid Palindrome

### 题目本质

这题不是计数题，也不是查重题。  
它的本质是：

**按题目规则跳过无关字符后，用左右双指针判断字符串是否首尾对称。**

---

### 为什么不是计数题

因为这题不关心每个字符出现了几次。  
它关心的是：

- 左边当前字符是什么
- 右边当前字符是什么
- 两边在跳过无关字符后，是否能一一对应

所以这题更像：

**字符串规则过滤 + 双指针比较**

---

### 核心规则

1. 只看 **字母和数字**
2. 空格、逗号、冒号等字符都要 **跳过**
3. 大小写要先统一，再比较
4. 如果中途有一次不相等，直接返回 `False`
5. 如果整轮比较都没有出错，最后返回 `True`

---

### 变量分别负责什么

#### `left`

指向左边当前要检查的字符。

#### `right`

指向右边当前要检查的字符。

---

### 主逻辑骨架

1. 先让 `left` 和 `right` 分别从字符串两端开始
2. 当左边不是字母或数字时，`left += 1`
3. 当右边不是字母或数字时，`right -= 1`
4. 当左右都已经是合法字符时：
   - 统一成小写
   - 比较是否相等
   - 不相等：`return False`
   - 相等：继续往中间走
5. 循环结束后返回 `True`

---

### 为什么这里必须用 `if / elif / else`

因为在每一轮循环中，只应该处理一种情况：

1. 左边不合法，就只跳过左边
2. 否则右边不合法，就只跳过右边
3. 否则才比较左右字符

如果写成三个并列 `if`，就可能出现：

- 左边刚跳过
- 右边也刚跳过
- 这一轮还继续比较

这样会把本来只是“跳过字符”的一轮，误变成“可以比较”的一轮，逻辑就会出错。

---

### 最终代码

```python
class Solution:
    def isPalindrome(self, s: str) -> bool:
        left = 0
        right = len(s) - 1

        while left < right:
            if not s[left].isalnum():
                left += 1
            elif not s[right].isalnum():
                right -= 1
            else:
                if s[left].lower() == s[right].lower():
                    left += 1
                    right -= 1
                else:
                    return False

        return True
```

---

### 易错点

#### 把这题当成计数题

这题不是统计次数，而是双指针比较。

#### 把无关字符直接拿去比较

题目明确要求只看字母和数字，所以空格、标点都要跳过。

#### 忘记统一大小写

`A` 和 `a` 在这题里应该视为相同。

#### 用三个并列 `if`

这样会导致同一轮里既跳过字符又继续比较，顺序容易出错。

####  把 `return True` 写进 `while` 里面

`return True` 应该写在整个 `while` 循环结束之后。

---

### 一句话总结

**这题是“跳过无关字符后，用双指针判断首尾是否对称”。**

## 541. Reverse String II

### 题目本质

这题不是整体双指针从字符串两端往中间收。  
它的本质是：

**外层按块处理，内层在每一块里用双指针反转前 `k` 个字符。**

---

### 为什么不是“整体双指针题”

因为题目规则不是整体反转，而是：

- 每 `2k` 个字符看成一组
- 每组只反转前 `k` 个
- 后 `k` 个不动

所以整题更像：

**按块处理字符串**

而不是整体首尾对换。

---

### 正确理解方式

这题可以分成两层：

#### 第一层：按块处理

- 当前块从 `start` 开始
- 下一块直接从 `start + 2 * k` 开始

#### 第二层：块内反转

- 在当前块中，只反转前 `k` 个字符
- 这一小段内部再用左右双指针交换

所以这题最标准的一句话是：

**外层按块，内层双指针反转。**

---

### `for start in range(0, len(chars), 2 * k)` 的含义

这一行代码表示：

- 从 `0` 开始
- 每次跳 `2 * k`
- 逐个拿到每一块的起点 `start`

也就是说：

- 第一块起点：`0`
- 第二块起点：`2 * k`
- 第三块起点：`4 * k`
- ...

它不是逐个字符扫描，  
而是在逐个找到“每个块从哪里开始”。

---

### 为什么字符串要先转成 `list`

Python 里的字符串 `str` 不能直接改某个位置的字符。  
但这题需要交换字符位置，所以要先写：

```python
chars = list(s)
```

比如：

```python
s = "abcd"
chars = list(s)
```

会变成：

```python
['a', 'b', 'c', 'd']
```

这样才能交换字符位置。

---

### 当前块里反转范围怎么确定

当前块从 `start` 开始时：

- 左边界：`left = start`
- 理论右边界：`start + k - 1`

但为了防止越界，要写成：

```python
right = min(start + k - 1, len(chars) - 1)
```

这表示：

- 正常情况下，反转到 `start + k - 1`
- 如果字符串已经快结束了，就反转到最后一个字符为止

---

### 为什么 `range` 里不用 `len(chars) - 1`

因为：

```python
range(0, len(chars), 2 * k)
```

里的 `len(chars)` 是“上限”，本身不会被取到。  
而 `min(..., len(chars) - 1)` 里的 `len(chars) - 1` 是“最后一个合法下标”。

两者表示的不是同一件事。

---

### 块内反转怎么做

在当前块内部：

- `left` 指向左边
- `right` 指向右边
- 当 `left < right` 时，交换两个位置的字符
- 然后 `left += 1`，`right -= 1`

这部分就是熟悉的双指针交换。

---

### 最终代码

```python
class Solution:
    def reverseStr(self, s: str, k: int) -> str:
        chars = list(s)

        for start in range(0, len(chars), 2 * k):
            left = start
            right = min(start + k - 1, len(chars) - 1)

            while left < right:
                chars[left], chars[right] = chars[right], chars[left]
                left += 1
                right -= 1

        return "".join(chars)
```

---

### 易错点

#### 把这题当成整体双指针题

整题主逻辑是按块，不是整体首尾相向。

#### 外层不是每次 `+1`

题目要求每 `2k` 处理一次，所以 `start` 每次应该跳 `2 * k`。

#### 忘记字符串不能直接改

必须先写：

```python
chars = list(s)
```

#### 忘记控制右边界

如果直接写 `start + k - 1`，可能越界。  
所以要用：

```python
min(start + k - 1, len(chars) - 1)
```

#### 最后直接返回 `chars`

`chars` 是列表，题目要的是字符串，所以最后必须：

```python
return "".join(chars)
```

---

### 一句话总结

**这题是“外层按 `2k` 分块，内层用双指针反转每块的前 `k` 个字符”。**

# 242. Valid Anagram

## 题目要我返回什么

返回两个字符串 `s` 和 `t` 是否为字母异位词，也就是返回 `True / False`。

---

## 题目本质

这题不是比较两个字符串的字符位置，而是比较：

**两个字符串中，每个字符出现的次数是否完全一样。**

例如：

- `s = "anagram"`
- `t = "nagaram"`

虽然顺序不同，但每个字符出现的次数一样，所以返回 `True`。

---

## 主路线

这题适合用 **哈希表 / 字典**。

原因是：

**字典非常适合统计“某个字符出现了多少次”。**

做法：

1. 先判断两个字符串长度是否相同
2. 若不同，直接返回 `False`
3. 用字典统计 `s` 中每个字符出现次数
4. 再遍历 `t`，对字典中的对应字符减 1
5. 如果出现字符不存在，或者减到负数，直接返回 `False`
6. 若整个过程没出问题，返回 `True`

---

## 需要维护的变量

- `count`：字典，用于统计字符次数

---

## 代码顺序

1. 先判断长度是否相等
2. 创建空字典 `count`
3. 遍历 `s`，统计字符次数
4. 遍历 `t`，逐个消耗 `count`
5. 若出现异常情况，返回 `False`
6. 最后返回 `True`

---

## 最小代码

```python
def isAnagram(s, t):
    if len(s) != len(t):
        return False

    count = {}

    for ch in s:
        if ch in count:
            count[ch] += 1
        else:
            count[ch] = 1

    for ch in t:
        if ch not in count:
            return False
        else:
            count[ch] -= 1
            if count[ch] < 0:
                return False

    return True
```

---

## 为什么第二个循环要做两层判断

### 1. `if ch not in count`

表示：

**`t` 中出现了 `s` 里根本没有的字符。**

例如：

- `s = "abc"`
- `t = "abd"`

这里 `d` 不在 `s` 中，所以直接 `False`。

---

### 2. `if count[ch] < 0`

表示：

**这个字符虽然在 `s` 中存在，但它在 `t` 中出现得更多。**

例如：

- `s = "aab"`
- `t = "abb"`

`b` 在 `s` 中只有 1 个，但在 `t` 中有 2 个，所以会减到负数。

---

## 易错点

- 长度不同要先返回 `False`
- `count[ch] += 1` 不能直接乱写，第一次出现时字典里还没有这个键
- 第二个循环里不是只检查 `ch not in count` 就够了，还要检查减完后是否小于 0
- 这题本质不是比较位置，而是比较“字符组成 + 次数”

---

## 我今天对这题的核心理解

**这题不是比字符顺序，而是比两个字符串中每种字符的数量是否完全一致。**

# 56. Merge Intervals

## 题目要我返回什么

返回所有重叠区间合并后的结果区间列表。

---

## 题目本质

这题本质上是在做区间的“并集整理”。

关键问题是：

**两个区间是否重叠，取决于后一个区间的左边界，是否小于等于前一个区间的右边界。**

即：

```python
current[0] <= result[-1][1]
```

若成立，则说明区间重叠或相接，可以合并。

---

## 主路线

这题适合：

**先排序，再从左到右扫描。**

原因：

如果不排序，就无法稳定地从左到右判断当前区间和前面结果区间的关系。

做法：

1. 先按左边界排序
2. 创建结果列表 `result`
3. 先把第一个区间放进 `result`
4. 从第二个区间开始遍历
5. 若与 `result` 最后一个区间重叠，则合并
6. 若不重叠，则作为新区间加入 `result`

---

## 需要维护的变量

- `intervals`：排序后的原始区间列表
- `result`：已经整理好的合并结果
- `current`：当前正在处理的区间

---

## 代码顺序

1. 先处理空输入
2. 对 `intervals` 排序
3. 初始化 `result = [intervals[0]]`
4. 从 `intervals[1:]` 开始遍历
5. 若重叠，则更新右边界
6. 若不重叠，则加入新区间
7. 最后返回 `result`

---

## 最小代码

```python
class Solution:
    def merge(self, intervals):
        if not intervals:
            return []

        intervals.sort()
        result = [intervals[0]]

        for current in intervals[1:]:
            if current[0] <= result[-1][1]:
                result[-1][1] = max(current[1], result[-1][1])
            else:
                result.append(current)

        return result
```

---

## 为什么要先写 `if not intervals`

```python
if not intervals:
    return []
```

意思是：

**如果 `intervals` 是空列表，就直接返回空列表。**

原因：

后面会写：

```python
result = [intervals[0]]
```

如果 `intervals` 是空的，那么 `intervals[0]` 会报错。

---

## 为什么要先排序

```python
intervals.sort()
```

作用：

**按区间左边界从小到大排序。**

排序后才能从左到右稳定比较。

例如：

```python
[[8,10], [1,3], [2,6]]
```

排序后变成：

```python
[[1,3], [2,6], [8,10]]
```

---

## `intervals[1:]` 是什么

表示：

**从下标 1 开始，到最后。**

也就是：

**从第二个区间开始往后遍历。**

因为第一个区间已经先放进 `result` 里了。

---

## `result[-1]` 是什么

表示：

**`result` 列表中的最后一个元素。**

在这题里，它代表：

**最后一个已经整理好的区间。**

例如：

```python
result = [[1, 6], [8, 10]]
```

那么：

- `result[-1]` 是 `[8, 10]`
- `result[-1][0]` 是 `8`
- `result[-1][1]` 是 `10`

---

## 为什么只和 `result[-1]` 比

因为区间已经排序好了。

当前新区间只可能影响：

**结果列表里最后一个区间。**

不会再回头影响更早的区间。

---

## 为什么重叠时只更新右边界

因为排序后：

- 左边界更小的区间已经在前面
- 当前区间不可能把左边界再往左推

所以若重叠，只需要更新右边界：

```python
result[-1][1] = max(current[1], result[-1][1])
```

---

## `append(current)` 是什么

```python
result.append(current)
```

表示：

**把整个当前区间，加入结果列表最后面。**

不是加一个数字，而是加一个完整区间。

例如：

```python
result = [[1, 6]]
current = [8, 10]
result.append(current)
```

结果变成：

```python
[[1, 6], [8, 10]]
```

---

## 手推例子

输入：

```python

```

### 第一步：排序

本来就有序：

```

```

```

### 第五步：`current = [15,18]`

```

不成立，不重叠，加入结果：

```python

```

```python

```

# Day 12 LeetCode 刷题思路整理

## 144. Binary Tree Preorder Traversal

### 题目本质

这题要求返回二叉树的**前序遍历**结果。

前序遍历的固定顺序是：

**根 -> 左 -> 右**

也就是说，对于任意一个节点：

1. 先处理当前节点自己
2. 再处理左子树
3. 最后处理右子树

---

### 为什么适合用递归

因为二叉树的左子树、右子树，本身还是二叉树。

所以当我们确定了：

- 当前节点怎么处理
- 空节点怎么处理

整棵树就可以按同样规则一层一层递归下去。

---

### 递归函数的核心逻辑

假设递归函数叫：

```python
preorder(node)
```

它表示：

**把以 `node` 为根的这棵树，按前序遍历处理掉。**

那么逻辑就是：

#### 1. 先处理 base case

如果当前节点为空，直接返回。

```python
if not node:
    return
```

#### 2. 当前节点不为空时

按前序顺序做三件事：

1. 把当前节点值加入结果数组
2. 递归左子树
3. 递归右子树

也就是：

```python
result.append(node.val)
preorder(node.left)
preorder(node.right)
```

---

### 为什么最后返回 `result`

因为递归函数 `preorder(node)` 的职责是：

**负责遍历过程。**

真正用来存答案的是外部的：

```python
result = []
```

所以：

- `preorder(root)` 是启动整棵树的遍历
- `result` 才是最终结果

因此最后返回的是：

```python
return result
```

而不是 `return preorder(root)`。

---

### 这题最关键的理解

这题最重要的不是背代码，而是先真正明白：

- 前序遍历为什么是“先自己，再左，再右”
- 为什么空节点要立刻返回
- 为什么结果存进 `result`
- 为什么递归函数只是过程，不是答案本身

---

### 标准代码

```python
class Solution:
    def preorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        result = []

        def preorder(node):
            if not node:
                return

            result.append(node.val)
            preorder(node.left)
            preorder(node.right)

        preorder(root)
        return result
```

---

### 一句话总结

前序遍历就是：

**先访问当前节点，再递归左子树，最后递归右子树。**

## 56. Merge Intervals

### 题目本质

这题给你一组区间，要你把所有**有重叠的区间合并起来**。

例如：

```python
[[1,3],[2,6],[8,10],[15,18]]
```

因为：

- `[1,3]` 和 `[2,6]` 有重叠

所以应该合并成：

```python
[[1,6],[8,10],[15,18]]
```

---

### 这题最关键的前提：先排序

如果区间是乱的，我们就很难从左到右稳定判断谁和谁能合并。

所以第一步必须先按区间起点排序：

```python
intervals.sort(key=lambda x: x[0])
```

排序之后，区间会按左端点从小到大排列。

这样做的意义是：

**后面只需要从左到右扫描，就能判断当前区间和前面最后一个区间是否重叠。**

---

### 合并的核心判断

假设当前已经有一个结果数组 `result`。

我们每次拿一个新区间 `cur` 去和 `result` 里最后一个区间比较。

假设：

- 最后一个已合并区间是 `last`
- 当前区间是 `cur`

如果：

```python
cur[0] <= last[1]
```

说明：

**当前区间的起点落在上一个区间的结尾之前或正好相接。**

这就代表它们有重叠，可以合并。

---

### 合并时怎么做

如果能合并，不需要新增区间，而是直接更新最后一个区间的右端点：

```python
last[1] = max(last[1], cur[1])
```

因为合并后的右边界，应该取更大的那个结尾。

---

### 什么时候不能合并

如果：

```python
cur[0] > last[1]
```

说明当前区间和最后一个区间已经断开了，没有重叠。

那就只能把当前区间作为一个新区间加入结果数组。

---

### 整体流程

1. 先按起点排序
2. 创建结果数组
3. 从左到右扫描每个区间
4. 看当前区间是否和结果数组最后一个区间重叠
5. 能重叠就更新右端点
6. 不能重叠就直接加入结果数组

---

### 这题最关键的理解

这题真正的核心不是“背模板”，而是先明白：

- 为什么必须先排序
- 为什么排序后可以只看“当前区间”和“结果数组最后一个区间”
- 为什么重叠时只更新右边界
- 为什么不重叠时要新开一个区间

---

### 标准代码

```python
class Solution:
    def merge(self, intervals: List[List[int]]) -> List[List[int]]:
        intervals.sort(key=lambda x: x[0])

        result = []

        for interval in intervals:
            if not result or interval[0] > result[-1][1]:
                result.append(interval)
            else:
                result[-1][1] = max(result[-1][1], interval[1])

        return result
```

---

### 一句话总结

这题的主线就是：

**先排序，再从左到右扫描；能合并就更新最后一个区间的右端点，不能合并就加入新区间。**

---

今天这两题虽然类型不同，但都体现了一个很重要的思路：

### 144

先明确“遍历顺序”，再把顺序翻译成递归代码。

先明确“区间什么时候算重叠”，再把判断翻译成排序 + 扫描代码。

- 代码里的每一步是在实现哪条规则？

这也是今天刷题里最重要的进步。

# 二、二叉树三种基础遍历

## 1. 前序遍历 Preorder

顺序：

```text
根 -> 左 -> 右
```

递归模板：

```python
result = []

def traverse(node):
    if node is None:
        return

    result.append(node.val)
    traverse(node.left)
    traverse(node.right)
```

关键理解：

- 一到当前节点，就先记录它
- 然后递归左子树
- 最后递归右子树

---

## 2. 中序遍历 Inorder

顺序：

```text
左 -> 根 -> 右
```

递归模板：

```python
result = []

def traverse(node):
    if node is None:
        return

    traverse(node.left)
    result.append(node.val)
    traverse(node.right)
```

关键理解：

- 先把左子树处理完
- 再记录当前节点
- 最后处理右子树

### 这题最关键的一句话

**中序遍历记录当前节点，不要求右边也结束，只要求左边先结束。**

---

## 3. 后序遍历 Postorder

顺序：

```text
左 -> 右 -> 根
```

递归模板：

```python
result = []

def traverse(node):
    if node is None:
        return

    traverse(node.left)
    traverse(node.right)
    result.append(node.val)
```

关键理解：

- 左子树先处理完
- 右子树再处理完
- 最后才记录当前节点

### 这题最关键的一句话

**后序遍历里，当前节点一定是在左右子树都处理完以后才记录。**

---

## 4. 三种遍历真正的本质区别

同一个递归框架里，真正变的不是树，也不是递归，而是：

**当前节点值加入结果数组的位置。**

### 前序

```python
append
left
right
```

### 中序

```python
left
append
right
```

### 后序

```python
left
right
append
```

所以以后看到遍历题，先想的不是名字，而是：

> **当前节点值应该放在左递归前、中间、还是右递归后？**

# 三、94. Binary Tree Inorder Traversal

## 题目本质

中序遍历顺序是：

```text
左子树 -> 根节点 -> 右子树
```

所以这题的关键不是重新发明一种递归，而是：

**把 `append(node.val)` 放到两次递归中间。**

---

## 最小代码

```python
class Solution:
    def inorderTraversal(self, root):
        result = []

        def traverse(node):
            if node is None:
                return

            traverse(node.left)
            result.append(node.val)
            traverse(node.right)

        traverse(root)
        return result
```

---

## 思路总结

定义 `traverse(node)` 表示：

> 把以 `node` 为根的这棵子树按中序遍历完，并把结果加入 `result`

如果当前节点为空，直接返回。  
否则：

1. 先递归遍历左子树
2. 再记录当前节点
3. 最后递归遍历右子树

---

## 时间复杂度

```text
O(n)
```

每个节点访问一次。

## 空间复杂度

```text
O(h)
```

`h` 是树高，递归栈最坏可到 `O(n)`。

---

## 易错点

### 1. `append` 放错位置

- 放最前面：前序
- 放中间：中序
- 放最后：后序

### 2. 忘记终止条件

```python
if node is None:
    return
```

### 3. 没理解“递归处理的是整棵子树”

`traverse(node.left)` 不是只看左孩子一下，而是把左边整棵子树都处理完。

# 四、145. Binary Tree Postorder Traversal

## 题目本质

后序遍历顺序是：

```text
左子树 -> 右子树 -> 根节点
```

所以关键点就是：

**把 `append(node.val)` 放在两次递归之后。**

---

## 最小代码

```python
class Solution:
    def postorderTraversal(self, root):
        result = []

        def postorder(node):
            if node is None:
                return

            postorder(node.left)
            postorder(node.right)
            result.append(node.val)

        postorder(root)
        return result
```

---

## 思路总结

定义 `postorder(node)` 表示：

> 把以 `node` 为根的子树按后序遍历完，并把结果加入 `result`

如果当前节点为空，直接返回。  
否则：

1. 先递归左子树
2. 再递归右子树
3. 最后记录当前节点

---

## 时间复杂度

```text
O(n)
```

## 空间复杂度

```text
O(h)
```

---

## 易错点

### 1. 误以为后序和中序差别不大

其实本质区别就在于：

- 中序：`left -> append -> right`
- 后序：`left -> right -> append`

### 2. 没意识到根节点一定最后记录

因为必须左右子树都走完，才轮到根。

# 五、递归里的 return 到底回哪里

今天树题里最关键的基础理解之一：

**递归里的 `return` 不是直接回最外层，而是回到“调用当前函数的那一层”，继续执行后面的代码。**

比如：

```python
def traverse(node):
    if node is None:
        return

    traverse(node.left)
    result.append(node.val)
    traverse(node.right)
```

当 `traverse(node.left)` 里遇到空节点并 `return` 时，程序会：

- 回到当前这一层
- 继续执行下一句 `result.append(node.val)`

所以可以记一句：

> **递归里的 return，本质上是把当前子问题处理完，然后回到调用点的下一步。**

# 六、104. Maximum Depth of Binary Tree（DFS 初见面）

## 题目本质

题目问的是：

> 从根节点出发，到最远叶子节点，最长一条路径一共有多少层

例如：

```text
    1
   / \
  2   3
 /
4
```

最长路径是：

```text
1 -> 2 -> 4
```

所以最大深度是：

```text
3
```

---

## 这题和遍历题最大的不同

前面的遍历题是在做：

> 按某种顺序访问节点，并把节点值收集进数组

但这题不是收集顺序，而是：

> **让递归函数返回“这棵子树有多深”这个答案**

所以这题是 DFS 的第一种很重要的形式：

**返回值型 DFS**

---

## 递归函数的真正含义

定义：

```python
def maxDepth(node):
```

它的人话含义必须是：

> **返回“以 node 为根的这棵树”的最大深度**

---

## 最关键的递推公式

```python
maxDepth(node) = max(maxDepth(node.left), maxDepth(node.right)) + 1
```

含义：

- 先分别求左子树最大深度
- 再分别求右子树最大深度
- 取两者中较大的那个
- 再加上当前节点这一层

这里的 `+1` 是关键：

> **表示把当前节点自己这一层也算进去**

---

## 最小代码

```python
class Solution:
    def maxDepth(self, root):
        if root is None:
            return 0

        left_depth = self.maxDepth(root.left)
        right_depth = self.maxDepth(root.right)

        return max(left_depth, right_depth) + 1
```

---

## 为什么空节点返回 0

因为空节点本身不存在，所以没有层数。

可以直接记：

- 空树深度：`0`
- 单个节点的树深度：`1`

---

## 为什么叶子节点深度是 1

叶子节点左右孩子都是空，所以：

```python
maxDepth(leaf) = max(0, 0) + 1 = 1
```

也就是说：

- 左右空节点先返回 `0`
- 叶子节点第一次真正算出深度 `1`

---

## 为什么节点 2 的深度是 2

以节点 `2` 为根的子树是：

```text
  2
 /
4
```

一共有两层：

- 第一层：节点 `2`
- 第二层：节点 `4`

所以深度是 `2`

公式上看：

```python
maxDepth(2) = max(maxDepth(4), maxDepth(None)) + 1
            = max(1, 0) + 1
            = 2
```

---

## 这题最关键的执行顺序

这题不是从上往下直接数出来的，而是：

1. 先 DFS 一路往下递归
2. 遇到空节点，返回 `0`
3. 再在回溯过程中，从叶子节点开始一层层向上计算答案

所以可以记一句：

> **这题本质上是先 DFS 到底，再在回溯时自下而上求深度。**

---

## 思路总结（适合面试或笔记复述）

定义 `maxDepth(node)` 表示返回以 `node` 为根的二叉树最大深度。

如果当前节点为空，返回 `0`。  
否则，当前节点的最大深度等于：

- 左子树最大深度
- 右子树最大深度

中的较大值，再加上当前节点这一层。

因此递推公式为：

```python
maxDepth(node) = max(maxDepth(node.left), maxDepth(node.right)) + 1
```

---

## 时间复杂度

```text
O(n)
```

每个节点访问一次。

## 空间复杂度

```text
O(h)
```

`h` 为树高，递归栈最坏可到 `O(n)`。

---

## 易错点

### 1. 把 DFS 理解成单纯遍历

这题不是为了“按顺序访问节点”，而是为了“让左右子树返回深度答案”。

### 2. 以为空节点也在记录深度

不是。空节点只是返回 `0`，真正第一次算出深度的是叶子节点。

### 3. 不知道 `+1` 在算什么

`+1` 表示要把当前节点自己这一层也算进去。
