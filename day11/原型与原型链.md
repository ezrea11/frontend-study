# Day 11 前端笔记：原型与原型链

## 1. 今天这部分到底在学什么

今天不是死记硬背 `prototype`、`__proto__`、`new` 的定义。

今天真正要搞清的是这几个问题：

1. 为什么很多同类对象可以共用同一个方法
2. 为什么实例自己没有某个方法，却还能调用成功
3. `new` 到底帮我们做了什么
4. `prototype` 和 `__proto__` 到底分别是谁的

---

## 2. 从最普通的对象开始

先看一个普通对象：

```javascript
const person = {
  name: "James",
  sayHi: function () {
    console.log("Hi");
  }
};
```

这里很直接：

- `name` 是 `person` 自己的属性
- `sayHi` 也是 `person` 自己的方法

也就是说，普通对象可以理解成：

**一个装属性和方法的盒子。**

---

## 3. 为什么会需要 prototype

如果只有一个对象，这样写没有问题。

但如果我要很多同类对象：

```javascript
const person1 = {
  name: "James",
  sayHi: function () {
    console.log("Hi, I am " + this.name);
  }
};

const person2 = {
  name: "Sky",
  sayHi: function () {
    console.log("Hi, I am " + this.name);
  }
};
```

这时候会发现：

- `name` 不同，这是合理的
- 但 `sayHi` 的逻辑完全一样

问题就在这里：

**同样的方法被重复写了很多遍。**

所以就会想：

**能不能把“所有同类对象都要用的方法”放到一个公共区域里？**

这就是 `prototype` 出场的原因。

---

## 4. prototype 的当前阶段理解

当前阶段最适合的理解是：

**`Person.prototype` 是给 `Person` 这类对象准备的公共方法区。**

也就是说：

- 每个对象自己的数据，放在实例自己身上
- 大家共用的方法，放在 `prototype` 上

---

## 5. 构造函数是什么

```javascript
function Person(name) {
  this.name = name;
}
```

当前阶段先这样理解：

**构造函数就是一个用来批量创建同类对象的函数。**

比如：

```javascript
const p1 = new Person("James");
const p2 = new Person("Sky");
```

这里：

- `p1` 是一个新对象
- `p2` 也是一个新对象
- 它们都属于 `Person` 这一类对象

---

## 6. this.name = name 到底在做什么

```javascript
function Person(name) {
  this.name = name;
}
```

在 `new Person("James")` 这类写法里，`this` 会指向新创建出来的那个对象。

所以：

```javascript
this.name = name;
```

本质上是在做：

```javascript
p1.name = "James";
```

所以 `name` 是每个实例自己的数据。

这也是为什么：

- `p1.name` 可以是 `James`
- `p2.name` 可以是 `Sky`

因为每个对象都保存自己的 `name`。

---

## 7. 为什么 sayHi 更适合放到 prototype 上

```javascript
function Person(name) {
  this.name = name;
}

Person.prototype.sayHi = function () {
  console.log("Hi, I am " + this.name);
};
```

因为：

- `name` 是每个对象都不同的数据，所以放实例上
- `sayHi` 是所有对象都能共用的行为，所以放 `prototype` 上

### 错误但能运行的写法

```javascript
function Person(name) {
  this.name = name;
  this.sayHi = function () {
    console.log("Hi, I am " + this.name);
  };
}
```

这也能运行，但有问题：

**每次 `new Person(...)` 都会重新创建一份新的 `sayHi` 函数。**

比如：

```javascript
const p1 = new Person("James");
const p2 = new Person("Sky");

console.log(p1.sayHi === p2.sayHi); // false
```

说明：

- `p1` 有自己的一份 `sayHi`
- `p2` 也有自己的一份 `sayHi`
- 它们不是同一个函数对象

而如果写在原型上：

```javascript
function Person(name) {
  this.name = name;
}

Person.prototype.sayHi = function () {
  console.log("Hi, I am " + this.name);
};

const p1 = new Person("James");
const p2 = new Person("Sky");

console.log(p1.sayHi === p2.sayHi); // true
```

说明：

**所有实例共享同一份 `sayHi`。**

---

## 8. 什么叫“函数有几份”

这里一定要区分两个问题：

### 问题 1：函数有几份？

这是在问：

- `p1.sayHi` 和 `p2.sayHi` 是不是同一个函数

### 问题 2：函数从哪里找到？

这是在问：

- `p1` 自己没有 `sayHi`，为什么还能调用到

这两个问题不是一回事。

---

## 9. hasOwnProperty 是什么

`hasOwnProperty("xxx")` 的作用是判断：

**某个属性是不是对象自己身上直接拥有的。**

例如：

```javascript
const person = {
  name: "James"
};

console.log(person.hasOwnProperty("name")); // true
console.log(person.hasOwnProperty("age"));  // false
```

放到当前例子里：

```javascript
function Person(name) {
  this.name = name;
}

Person.prototype.sayHi = function () {
  console.log("Hi, I am " + this.name);
};

const p1 = new Person("James");

console.log(p1.hasOwnProperty("name"));   // true
console.log(p1.hasOwnProperty("sayHi"));  // false
```

说明：

- `name` 是 `p1` 自己的属性
- `sayHi` 不是 `p1` 自己的属性，而是在原型上

注意：

**能访问到，不代表它是对象自己直接有的。**

---

## 10. prototype 和 __proto__ 的区别

这一块非常容易混。

### `Person.prototype`

它是：

**构造函数 `Person` 的公共方法区**

```javascript
Person.prototype
```

### `p1.__proto__`

它是：

**对象 `p1` 往上查找时连接到的地方**

```javascript
p1.__proto__
```

### 关键关系

在当前例子里：

```javascript
p1.__proto__ === Person.prototype
```

这句话的意思是：

**`p1` 往上找属性时，会去 `Person.prototype` 上找。**

### 为什么它们打印结果一样

因为它们在当前例子里指向同一个对象。

但角色不同：

- `Person.prototype`：从函数角度看，是公共方法区
- `p1.__proto__`：从实例角度看，是往上找的连接

---

## 11. new 到底帮我们做了什么

当执行：

```javascript
const p1 = new Person("James");
```

当前阶段先记住这 4 步：

### 第 1 步：创建一个新对象

可以先脑补成：

```javascript
const obj = {};
```

### 第 2 步：把这个新对象连到 `Person.prototype`

效果上可以理解成：

```javascript
obj.__proto__ === Person.prototype
```

### 第 3 步：执行构造函数，并让 `this` 指向这个新对象

于是：

```javascript
this.name = name;
```

相当于：

```javascript
obj.name = "James";
```

### 第 4 步：把这个对象返回出来

最后这个对象被赋值给：

```javascript
const p1
```

所以，`new` 的关键不是复制某个方法，而是：

**创建实例对象，并把它连接到 `Person.prototype`。**

---

## 12. 为什么没有 new 不会自动连到 Person.prototype

如果写：

```javascript
Person("James");
```

这只是普通函数调用。

不会自动做这些事：

1. 不会自动创建一个新对象
2. 不会自动把新对象连到 `Person.prototype`
3. 不会自动把这个对象返回出来

所以：

**在当前这套构造函数写法里，只有 `new Person(...)` 才会自动把实例连接到 `Person.prototype`。**

补充：

普通对象也有自己的原型链，只是默认不会连到 `Person.prototype`，而通常会连到 `Object.prototype`。

---

## 13. 为什么先创建 p1，后加 sayHi，p1 也能用

看代码：

```javascript
function Person(name) {
  this.name = name;
}

const p1 = new Person("James");

Person.prototype.sayHi = function () {
  console.log("Hi, I am " + this.name);
};

p1.sayHi();
```

最后仍然能成功。

原因不是：

- 创建 `p1` 时，已经把 `sayHi` 复制了一份进去

而是：

- 创建 `p1` 时，只建立了到 `Person.prototype` 的连接
- 以后每次访问对象自己没有的属性时，都会沿着这条连接去原型上现找

所以后来给 `Person.prototype` 新加了 `sayHi`，`p1` 仍然能找到。

也就是说：

**原型方法不是拷贝到实例里，而是访问时动态查找。**

---

## 14. 最小 demo

```javascript
function Person(name) {
  this.name = name;
}

Person.prototype.sayHi = function () {
  console.log("Hi, I am " + this.name);
};

const p1 = new Person("James");

console.log(p1.name); // James
console.log(p1.__proto__ === Person.prototype); // true
console.log(p1.hasOwnProperty("name")); // true
console.log(p1.hasOwnProperty("sayHi")); // false

p1.sayHi(); // Hi, I am James
```

---

## 15. 这段 demo 的 4 个核心结论

### 1. 为什么 `p1.name` 能直接访问到

因为在 `new Person("James")` 时，`this.name = name` 把 `name` 放到了 `p1` 自己身上。

### 2. 为什么 `p1.__proto__ === Person.prototype` 是 `true`

因为 `new Person(...)` 会让新对象连接到 `Person.prototype`。

### 3. 为什么 `p1.hasOwnProperty("sayHi")` 是 `false`

因为 `sayHi` 不在 `p1` 自己身上，而是在 `Person.prototype` 这个公共方法区里。

### 4. 为什么 `p1.sayHi()` 还能成功

因为 `p1` 自己没有 `sayHi` 时，会沿着原型链去 `Person.prototype` 上找；找到后由于调用形式是 `p1.sayHi()`，所以执行时 `this === p1`。

---


## 16. 查找与执行的完整顺序

当我们写：

```javascript
p1.sayHi()
```

可以把它拆成下面 6 步：

1. 先看 `p1` 自己有没有 `sayHi`
2. 没有
3. 再沿着原型链往上找
4. 在 `Person.prototype` 上找到了 `sayHi`
5. 然后以 `p1.sayHi()` 的形式执行它
6. 所以执行时 `this === p1`

这一段非常重要，因为它把两件事彻底分开了：

- **找函数**：`sayHi` 是从哪里找到的
- **执行函数**：函数执行时 `this` 指向谁

很多混乱，都是因为把这两步混在了一起。

## 17. Day 11 当前阶段最标准的一段口头解释

构造函数 `Person` 有一个公共方法区 `Person.prototype`。当执行 `new Person("James")` 时，会创建一个新对象 `p1`，并自动让 `p1.__proto__` 指向 `Person.prototype`。同时在构造函数执行时，`this` 指向新对象 `p1`，所以 `this.name = name` 会把 `name` 赋值到 `p1` 自己身上，也就是得到 `p1.name = "James"`。以后当 `p1` 自己没有某个方法，比如 `sayHi` 时，就会沿着原型链去 `Person.prototype` 上查找。

---

## 18. 今天最容易混淆的坑

### 坑 1：以为 `name` 是 `Person` 自己的属性

不是。

`name` 是在执行构造函数时，通过 `this.name = name` 放到实例自己身上的。

### 坑 2：以为 `p1` 连到的是某个具体方法，比如 `sayHi`

不是。

`p1` 连到的是整个 `Person.prototype` 公共区域。

### 坑 3：以为原型方法会在实例创建时被复制进去

不是。

实例保存的是到原型区的连接，方法是访问时再去查找的。

### 坑 4：以为 `hasOwnProperty("sayHi")` 是 `false` 就说明不能调用

不是。

它只是说明 `sayHi` 不是 `p1` 自己直接拥有的属性，不代表不能沿着原型链找到。

---

## 18. 今日一句话总结

**实例自己的数据放在实例上，大家共用的方法放在 `prototype` 上；`new` 会把实例连到 `prototype`，所以实例自己没有的方法，也能沿着原型链找到。**
